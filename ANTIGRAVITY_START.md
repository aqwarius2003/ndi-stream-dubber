# Первое задание для Antigravity

Откройте папку проекта `D:\audio_translator`. Для разработки выберите в селекторе Gemini 3.8 Flash и уровень High, если он доступен в вашем клиенте. Корневой файл [GEMINI.md](GEMINI.md) задаёт постоянные правила проекта. Настройки перевода находятся в [SPEC.md](SPEC.md). [Выбор модели](https://antigravity.google/docs/models) · [Правила рабочей папки](https://antigravity.google/docs/rules)

## Сообщение для первого чата

> Прочитай GEMINI.md, SPEC.md и раздел «Задача 1А» в ANTIGRAVITY_START.md. Реализуй задачу 1А для RU → EN. Дай команды запуска и проверки на целевом Linux-сервере. Выполни доступные проверки. Укажи, какие участки прошли с реальным NDI и облачными API, какие проверены локально и что нужно для оставшихся испытаний. Оставь рабочую точку для следующего прогона.

## Задача 1А

Последующее развёртывание планируется на VPS. Выдели интерфейсы источника и получателя аудио. После ручного селектора передавай получателю PCM 48 кГц, идентификатор эфира, язык и время на шкале программы. В пилоте этот получатель публикует NDI. Сетевое подключение клиента вынесено в [испытание сервиса на VPS](SPEC.md#будущий-сервис-на-vps).

**Результат.** На контрольном NDI-приёмнике оператор находит один источник `Dub_EN`, слышит английский перевод одного русского входа и может вручную выбрать, какая из двух работающих веток звучит под этим именем.

1. **Захват.** На сервере с NDI Runtime открой одну подписку на настраиваемый источник, подготовь PCM16 mono 16 кГц. Выдай блоки по 20 мс с номером, позицией в сэмплах и временем. Оба обработчика получают один и тот же исходный материал. Ограничь очереди и регистрируй потери с номерами блоков. Добавь режим воспроизведения WAV в реальном темпе через тот же тракт для повторяемых локальных проверок.
2. **Два перевода.** Для Gemini используй профиль Live Translate из SPEC с целевым языком `en` и выходной транскрипцией. Для Soniox используй односторонний перевод в `en` через `stt-rt-v6`. Только зафиксированный текст перевода направляй в потоковый TTS готовым голосом. Для обеих веток сохрани текст, аудио и привязку к контрольной записи для сравнения. Укажи реально использованные версии, доступ к API и форматы звука. Имена источника, модели и голоса вынеси в настройки, ключи читай из окружения.
3. **Выход и управление.** Приведи звук обеих веток к 48 кГц. Создай один NDI-публикатор и переключай его аудиовход. Для пилота достаточно локального управления со статусом обеих веток, предпрослушиванием и выбором языка и источника. До начала прогона оператор явно выбирает эфирную ветку. При её отказе публикатор продолжает существовать, а оператор видит предупреждение. Восстановление соединения обновляет готовность ветки. Запоздалое появление звука после отклонённой команды требует новой команды.
4. **Поставка.** Предоставь воспроизводимые команды запуска и остановки, пример конфигурации без секретов, версию NDI Runtime и используемой обвязки, результаты проверок ниже. Целевая среда сервера по SPEC — Linux. Местная разработка на Windows и тест с WAV позволяют двигаться до появления стенда. Если отсутствует SDK, ключ или сетевой источник, укажи конкретную зависимость и продолжи независимые проверки.

### Как принять задачу 1А

| Действие на стенде | Наблюдаемый результат |
|---|---|
| Подать размеченную русскую запись с вопросами, отрицаниями, названиями препаратов, числами и единицами | Обе ветки переводят те же фрагменты. На отдельном приёмнике слышен выбранный английский голос. Доступны записи для сверки. |
| Во время речи прервать Soniox. Предложение проигнорировать, отклонить или дать ему истечь | Выбор Soniox и имя `Dub_EN` сохраняются. Звук Gemini появляется в эфире только после принятой команды. |
| Испытать отдельно прямую команду и подтверждение для готового Gemini. Повторить с отставшим или молчащим резервом | При готовом резерве слышен актуальный перевод. При неготовом виден отказ в переключении. Позднее восстановление требует новой команды. |
| Восстановить Soniox и перезапустить селектор при выбранном Gemini. Затем вернуть Soniox вручную | Маршрут остаётся на Gemini до команды возврата. Записаны время команды, результат и пропуски или повторы на стыке. |
| Записать на одной временной шкале русский вход и выход контрольного NDI-приёмника | По каждой ветке привести число размеченных фрагментов, p50, p95, максимум, долю задержек свыше 3 с и число пропусков. Переключение измерить отдельно от команды до первого актуального слышимого слова. Ориентир 0,5 с относится к горячему готовому резерву и подлежит проверке. |

## После первого английского выхода

**Задача 1Б.** Добавить немецкий и проверить независимое переключение EN и DE. Сравнить горячий Gemini и запуск по команде. Перед нагрузочным прогоном согласовать оставшиеся семь языков, проверить для каждого перевод и голос, сверить квоты. Провести четырёхчасовой прогон одного языка и двухчасовой прогон девяти одновременных выходов по SPEC.

**Выбор основной ветки.** На тех же фразах сравнить искажения смысла, дозировок и отрицаний, задержку и пропуски. По биллингу привести стоимость часа на один и девять языков для голоса с текстом, отдельно для текста при выключенном TTS и для каждого режима резерва. Полный горячий резерв тарифицируется параллельно. Выбрать Soniox основным, если замеры подтвердят сопоставимое качество, задержку до 3 с и экономию с выбранным резервом.

**Этапы 2 и 3.** На втором этапе принимать текст при отключённом голосе, выдавать переключаемые дорожки WebVTT в эфир и файлы SRT для записи, сравнить DeepL Aure на том же материале. Собственный заранее обученный голос подключать на третьем этапе через интерфейс синтеза.
